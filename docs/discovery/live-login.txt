Runtime management

Running user unit: patchwork-mtgo-session.service.
This is a transient service, not installed for startup after reboot. Its lifetime
depends on the user's service manager/session remaining available.
Network/EOF/timeout failures exit 1 and can restart after 30 seconds; the service
allows at most three starts per ten-minute window. Each restart performs a new
login; seamless session resumption and acknowledgement replay are not implemented.
Authentication rejection, a challenge, or an incompatible protocol stops with
exit 2 and is not automatically retried. No CI configuration was added.

From the repository root:

Start (safe to call when already running):
  bash scripts/start-session.sh

Status:
  systemctl --user status patchwork-mtgo-session.service
  cat .local/status.json

Operational logs:
  journalctl --user -u patchwork-mtgo-session.service -f

Stop gracefully:
  systemctl --user stop patchwork-mtgo-session.service

Alternative stop signal for a directly launched process:
  touch .local/stop
The start script removes this stop marker before launching a new session.

Foreground launch:
  PYTHONPATH=src python3 -m patchwork_automaton.session --credentials ../.creds
Do not start a second connection while the service is active; stop it first.

Tests:
  PYTHONPATH=src python3 -m unittest discover -s tests -v
