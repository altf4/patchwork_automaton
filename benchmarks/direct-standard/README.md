# Direct Standard playback

Standard playback uses the direct path by default, including neural self-play, neural play against scripted opponents, and scripted demonstration games. RustMage owns the game, constructs each player's redacted observation and prepares legal choices and the model's numeric arrays inside the Rust library. Python batches the arrays, calls the existing inference service, samples a choice and asks Rust to apply it. Neural observations and actions do not pass through JSON or Python game-state objects. Existing scripted policies need a Python observation, so their own redacted view and chosen action use the compatibility JSON interface; neural views remain native. Game setup and occasional progress diagnostics also use JSON.

The engine is pinned to revision `046b25ef14671753a2eea6336bc1ce974b298253`, the revision used by the reference benchmark; it is not the latest RustMage checkout. Run `python3 scripts/build-direct-standard.py` from the project root. This invokes RustMage's shared resource guard, uses its offline Cargo cache and leaves the regular RustMage build untouched. The resulting library is `.local/direct-standard/target/release/libpatchwork_direct_standard.so`.

`verify_tensors.py` runs the reference engine and candidate engine in lockstep. It compares both redacted observations, every expanded legal action, all numerical feature arrays and actor-local recurrent history at every non-forced decision. `verify_privacy.py` additionally checks the opening private hands and tests that changing the opponent's hidden deck leaves the player's observations and tensors unchanged, and that non-actor, stale and foreign game handles are rejected. Both scripts deliberately use debug JSON for comparison; neither is used for timing.

`verify_harmonize.py` deliberately steers a scripted game to a Harmonize choice and checks the 250K model's Bargain-compatible encoding as well as both private views after the actual action. Run it against the frozen source that contains that checkpoint's Harmonize adapter.

`compare_direct.py` runs fresh CPU inference replicas with the same frozen checkpoint, schedules and 48 workers as the two-plus-two baseline, alternating phase order. It compares game outcomes and the recorded model inputs, action choices and model outputs. Use `--scripted` to compare neural play against a scripted opponent. Adjudicated games are reported separately because their partial trajectories need not match.

## Repeating the process

The benchmark uses the existing Standard self-play implementation, the exact frozen model and a matching RustMage reference library. On raytracer the original tested source snapshot is `/home/altf4/benchmarks/standard-ppo-100000-compact-20261028/selfplay-250k-20261029/source-harmonize-v1`, and the checkpoint is under that run's `treatment/run/checkpoints/round-0250/`. Both are external to Git. The manifests contain the source and checkpoint hashes; use those to verify the required snapshot before comparing results.

Build the library before running Standard playback. Set `DIRECT_STANDARD_LIBRARY` to override its location. The process checks the installed RustMage revision and the exact Standard encoder fingerprint, and checks model input dimensions; unsupported schemas and missing libraries fail rather than silently reverting. `PATCHWORK_STANDARD_PLAYBACK=python` explicitly selects the prior reference path for comparisons. The setting does not change the separate Foundations encoder or general RustMage API.

CPU inference replicas default to one TensorFlow intra-op thread each. Set `PATCHWORK_CPU_INFERENCE_INTRA_THREADS` to a positive integer before creating a collector to override that replica-only default. The setting takes precedence over the inherited `TF_NUM_INTRAOP_THREADS` for CPU replicas; it does not change the learner, TensorFlow inter-op threads or GPU replicas. Replica statistics report the configured intra-op count. The matched performance comparison is documented in the [direct-path profile](../direct-profile/README.md).

For future runs on raytracer, the default implementation is installed at `/home/altf4/benchmarks/standard-direct-intra1-20261031/source`, with the verified direct library in its default location. It uses the existing `/home/altf4/benchmarks/mtgo-cpu-gpu-20261024/venv` environment. A guarded 240-game 250K-model check of the replica thread default matched every game summary and all 19,104 recorded feature/action records. The Rust compiler is not installed on raytracer; rebuild through the guarded local build and copy the resulting library when the bridge changes.

For a future change, build through the RustMage resource guard, then run the privacy check, lockstep tensor/history check and Harmonize check against the same frozen source. Run a short matched preflight before timing the candidate against the Python pipeline with the same checkpoint and two-plus-two configuration. Use fresh workers and alternate phase order; record timeouts separately, compare the saved trajectories and check the source, model and library hashes after the run. No training is needed. Preserve the manifest and memory-guard results with the change.

The saved `launch-raytracer.sh` and command JSON files record the exact host paths and memory guard used here. They target this run's output directories and intentionally cannot overwrite existing results. For another run, copy them to a new experiment directory and update their paths before launching; keep the original artifacts intact.

## Results: raytracer, 2026-10-31

The frozen 250K checkpoint (SHA-256 `12f263e2024014574c96130fc707fee95cdb9837130e498f27d27661fa5ce623`) ran CPU inference with 48 game workers, two runners and two inference replicas for each player. Model weights were not updated. Each of two independent schedules was played once by each pipeline, 1,000 games per phase. The phase order was reversed for the second schedule. A separate 240-game preflight preceded the main run. Collection excludes worker/model startup, 48 warmup games and shutdown; game startup, observation, inference, action application and trajectory writing are included.

| Pair and order | Current Python pipeline | Direct Rust path |
| --- | ---: | ---: |
| 1: Python, then direct | 586.56 games/min (102.29 s) | 815.04 games/min (73.62 s) |
| 2: Direct, then Python | 570.99 games/min (105.08 s) | 834.74 games/min (71.88 s) |
| Combined, 2,000 games per pipeline | 578.67 games/min (207.37 s) | 824.77 games/min (145.50 s) |

The combined direct path produced **42.5% more games per minute** and used **29.8% less elapsed collection time** on these schedules. The second Python phase contains one 60-second game timeout; the corresponding direct game finished. That timeout affects the measured wall time and comparison, so these figures should not be interpreted as an exact prediction for every workload. This measurement preceded integration into the default playback dispatcher.

Of 2,000 matched games, **1,999 completed game summaries matched** in seed, result, winner, decisions, turn, life and action counts. The remaining baseline game timed out at turn 13; the candidate finished the game. All **162,427** recorded feature/action records from the 1,999 complete pairs were bit-for-bit equal. All **152** recorded feature/action records in the timed-out baseline game's partial trajectory also matched the corresponding candidate prefix; a completed baseline outcome is unavailable. The comparison records the one skipped completed-game comparison explicitly.

Inference outputs were not bit-for-bit identical between separately batched runs. Across the 162,427 complete-game records, 304 recurrent-memory records and 201 value/log-probability records exceeded the strict comparison tolerance (absolute `1e-6`, relative `1e-5`); the largest absolute log-probability difference was `1.53e-5`. The earlier [Python-versus-Python control](results/python-repeat-manifest.json) showed the same kind of small variation (maximum log-probability difference `1.34e-5`). Selected actions and encoded inputs nevertheless matched in all compared records. These checks establish equivalence for the exercised games and do not prove equivalence for every possible game.

A separate lockstep check on raytracer's frozen source covered **27 scripted games**, **20,098 private views**, **38,057 choices** and **10,022 encoded decisions**, including actor-local history. Both opening hands remained private; swapping the hidden opposing deck left the player's view and model inputs unchanged. The bridge rejected non-actor, stale and foreign-game action handles. A targeted game reached a two-choice Harmonize decision, matched its 250K-specific encoding and legal actions, applied a creature choice and matched both subsequent private views.

The full and preflight guards exited successfully; the minimum sampled available memory was 4.78 GiB and 5.08 GiB respectively. The tested direct library SHA-256 was `af836bdeac6d49fa6b2622344abbb1083220c3c920e3263d7bc6b70b8f1098a7`; the tested local and raytracer copies of the library and benchmark scripts matched. The model, frozen reference sources and library hashes were checked again after the run. Complete game records, rollout trajectories and timeout diagnostics remain at `/home/altf4/benchmarks/direct-standard-20261031/` on raytracer. The [full manifest](results/full/manifest.json), [preflight manifest](results/preflight/manifest.json), [lockstep result](results/lockstep.json), [privacy check](results/privacy-check.json), [Harmonize check](results/harmonize-check.jsonl), [timeout prefix](results/timeout-prefix.json) and memory guard samples are saved here.

## Default-path integration check

After integrating the bridge into the Standard playback dispatcher, two additional guarded 240-game comparisons used the same frozen 250K model on raytracer. All 240 neural self-play game summaries and 18,385 recorded feature/action records matched; all 240 games against the scripted opponent and 18,702 recorded feature/action records matched. The neural self-play run measured 485.5 versus 657.2 games/minute, and the scripted-opponent run measured 812.0 versus 1,076.4 games/minute, for the Python and direct paths respectively. These short runs verify the integration; the longer alternating-order experiment above is the better throughput comparison.

The model outputs had the same small separately batched floating-point differences described above. Both memory guards exited successfully.
